# Портал регламентов: шаблон для новой компании

Готовая архитектура портала ALIU без данных ALIU. Чтобы запустить портал в другой компании, скопируйте файл `index.html` из этой папки, заполните блок данных и опубликуйте страницу.

- Пример готового портала: https://quladun.github.io/reglament/portal/
- Пустой шаблон: https://quladun.github.io/reglament/template/

---

## 1. Архитектура

### 1.1. Структура схемы (что где лежит)

```
Компания (центр)
├── Владелец (CEO)
│   └── Бизнес-ассистент
├── Операционный директор (COO)
│   ├── Еженедельный отчёт COO
│   └── Вопросы: руководство
├── Отдел ×N (Продажи, Снабжение, Производство, Финансы…)
│   ├── Сотрудник / роль
│   │   └── Регламенты этой роли
│   ├── Регламенты отдела
│   └── Вопросы: отдел (анкета)
├── Общие правила
│   ├── Неделя компании · Спринты · Счета на оплату · Рабочие чаты
│   ├── Отпуска · Ввод нового сотрудника · Увольнение: доступы
│   └── Анкета для всех сотрудников
├── Справочники
│   ├── Ассортимент · Сроки · Рабочие таблицы · Глоссарий
│   └── Источники: откуда брать таблицы и регламенты
└── Закрытый раздел (только заглушки, без данных)
```

Схема строится автоматически: узлы раскладываются по кольцам. Первое кольцо — отделы, второе — сотрудники и регламенты отдела, третье — регламенты сотрудников. Пунктиром показаны связи между отделами (кто кому передаёт результат).

### 1.2. Типы узлов

| Тип | Цвет | Что это |
|---|---|---|
| `company` | жёлтый | Центр, ровно один |
| `dept` | фиолетовый | Отдел |
| `role` | голубой | Сотрудник или должность |
| `reg` | зелёный | Регламент |
| `general` | оранжевый | Общее правило для всех |
| `ref` | розовый | Справочник |
| `quiz` | бирюзовый | Анкета для сотрудников с кнопкой «Скопировать» |
| `lock` | серый | Закрытый раздел (только заглушка) |

### 1.3. Шаблон карточки регламента

Цель → исполнитель → когда и как часто → где (таблицы) → шаги → результат → правила и запреты → кому задавать вопросы.

### 1.4. Шаблон карточки сотрудника

Сотрудник · должность · отдел · руководитель · главный результат · город · часовой пояс · график · формат работы → обязанности → регламенты → анкета.

## 2. Устройство файла

Весь портал — это один файл `index.html`. В нём четыре части:

1. **Оформление** (CSS). Не трогать.
2. **НАСТРОЙКИ**: `CONFIG = {name:'…', subtitle:'…'}`. Здесь название компании.
3. **ДАННЫЕ КОМПАНИИ** — блок между строками `ДАННЫЕ КОМПАНИИ — НАЧАЛО` и `КОНЕЦ`. Меняется только он.
4. **ДВИЖОК** (граф, поиск, карточки). Не трогать.

### Как добавить узел

```js
node('id', 'тип', 'Название', 'id_родителя', ТЕКСТ);
x('id1', 'id2');   // пунктирная связь
```

- `id` — латиница без пробелов, уникальный.
- Ссылка на узел: `адрес_портала/#id`.
- Если у узла первого кольца длинное название, добавьте короткую подпись: `{short:'COO · Имя'}`.

### Помощники для текста

| Функция | Что делает |
|---|---|
| `p('…')` | Абзац |
| `sec('Заголовок', html)` | Раздел |
| `ul([...])` / `ol([...])` | Список / нумерованный список |
| `tbl(['Шапка',…], [[ячейки],…])` | Таблица |
| `meta({'Поле':'значение'})` | Блок «поле — значение» |
| `person({name,pos,dept,boss,result,city,tz,hours,fmt})` | Карточка сотрудника |
| `week([['День',[...]],…])` | Расписание по дням |
| `quiz('Заголовок',[вопросы])` | Анкета с кнопкой «Скопировать» |
| `tpl('текст')` | Блок шаблона с кнопкой «Скопировать» |
| `U`, `VAC` | Пометки «уточняется» и «вакансия» |
| `COMMON_Q` | Пять общих вопросов для любой анкеты |

## 3. Порядок запуска в новой компании

1. **Собрать источники** (таблица ниже). Файлы и ссылки присылайте Claude в чат.
2. **Оргструктура.** Компания → CEO/COO → отделы → сотрудники с подчинением.
3. **Регламенты.** Каждый документ раскладывается по отделу или роли по шаблону. Дубли сводятся в одну версию, противоречия выносятся на решение руководителю.
4. **Общие правила.** Неделя компании, спринты, оплаты, чаты, отпуска, ввод и увольнение. Переносятся почти без изменений, меняются только время и имена.
5. **Анкеты.** Разослать «Вопросы» каждого отдела. Ответами заполнить пометки «уточняется».
6. **Безопасность.** Проверить, что на портале нет паролей, реквизитов и личных контактов.
7. **Публикация** (раздел 5).

## 4. Источники: откуда брать информацию

| Что нужно | Где взять | Куда на портале |
|---|---|---|
| Оргструктура: должности, подчинение, обязанности, графики | Google-таблица оргструктуры: листы «Структура», «Информация о сотрудниках» | Центр, роли |
| Список таблиц и ссылок | Таск-трекер (в ALIU — YouGile → проект «Маркетплейсы \| WB/Ozon» → доска «Таблицы», колонки по отделам) | «Рабочие таблицы», «Ввод сотрудника» |
| Готовые регламенты | Там же: колонка «Регламенты» и доска «Документы»; Google Docs и Sheets по ссылкам | Зелёные узлы |
| Обязанности и чек-листы по дням | Таблица оргструктуры: листы «Обязанности …», «Чек-лист для …» | Роли, чек-листы |
| Отчёты руководителей | Таблица оргструктуры: листы «Регламент отчёта …» | Отчёты у COO, производства, финансов |
| Отпуска, увольнение, запуск товара | Таблица оргструктуры: соответствующие листы | Общие правила, продажи |
| ТЗ на поставки и производство, ассортимент | Таблица поставок: листы с инструкциями и справочником товаров | Регламенты продаж, «Ассортимент» |
| Процессы снабжения | Таблица операционного отдела: «Задачи по дням», инструкции | Регламенты снабжения |
| Контент | Облачный диск: фотосессии, инфографика | «Рабочие таблицы» |
| Чего нет в документах | Анкеты «Вопросы» → ответы сотрудников | Карточки и регламенты |

**Не переносить на портал:** пароли и PIN, банковские реквизиты, телефоны, почты и даты рождения сотрудников, контакты подрядчиков. На портале остаются только заглушки «в закрытом разделе». Ссылки на таблицы, где лежат пароли, указываются как путь в таск-трекере, без прямой ссылки.

## 5. Публикация на GitHub Pages

1. Создайте репозиторий на GitHub, например `reglament-company`.
2. Положите в него этот `index.html` (в корень или в папку).
3. Включите публикацию: Settings → Pages → Source: «Deploy from a branch» → `main` / root → Save.
4. Через 1–2 минуты сайт откроется по адресу `https://ИМЯ.github.io/reglament-company/`.
5. Обновление: заменить файл и закоммитить. Сайт обновится сам.

Публичный репозиторий виден всем в интернете. Чтобы закрыть доступ, нужен приватный репозиторий с платным тарифом GitHub или хостинг с паролем.

## 6. Как вести дальше

- Новые регламенты присылаются Claude в чат проекта: он раскладывает их по структуре и обновляет файл.
- Для каждой компании ведётся реестр материалов: что получено, куда разложено, какие вопросы открыты.
- Каждое изменение — отдельный коммит, поэтому история правок видна в GitHub.
